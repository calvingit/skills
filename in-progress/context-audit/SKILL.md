# 上下文审查

审查 Agent 实际会使用的上下文，减少冲突、重复和不必要的长期上下文，并让长期有效的规则由合适的位置维护。

## 流程

1. 确认审查范围，包括系统规则、`AGENTS.md`、项目规则、Skills、参考资料、Memory、工具说明、少样本示例（few-shot）及其他会进入上下文的内容。
2. 找出重复规则、互相冲突的要求、过时信息、适用范围错误，以及长期规则与临时任务信息混放等问题。
3. 判断内容应该长期保留、按需加载、移入 `references/`、由脚本或工具强制执行，还是直接删除。
4. 对每项建议说明当前问题、实际影响、建议位置和迁移风险；已有明确维护者的规则不要在其他位置重复定义。
5. 优先做最小调整，避免为了整理结构而重构整套提示词体系。

## 边界

这里只审查上下文组织和指令职责，不评价业务代码质量，也不负责重新设计完整的 Agent 架构。涉及行为改变时必须说明影响范围，不能只以减少上下文占用为理由修改内容。
