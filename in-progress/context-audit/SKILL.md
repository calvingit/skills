# Context Audit

审查 Agent 实际会消费的上下文，目标是减少冲突、重复和无效常驻信息，并让稳定规则处在正确的层级。

## Process

1. 确认审查范围，包括系统规则、AGENTS.md、项目规则、Skills、references、Memory、工具描述、few-shot 和其他会进入上下文的资料。
2. 标出重复规则、相互冲突的要求、过时事实、作用域错误、长期规则与任务临时信息混放等问题。
3. 判断内容应该继续常驻、按需加载、移动到 reference、交给脚本或工具保证，还是删除。
4. 对每项建议说明当前问题、影响、建议位置和迁移风险；已有明确 owner 的规则不要复制到其他层级。
5. 优先做最小调整，避免为了“整洁”重构整套提示词体系。

## 边界

这里只审查上下文组织和指令职责，不评价业务代码质量，也不负责重新设计完整 Agent 架构。涉及行为改变时必须指出影响范围，不能把压缩 token 当作唯一目标。
