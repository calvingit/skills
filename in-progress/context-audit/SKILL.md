# Context Audit

审查 Agent 实际会使用的上下文，目标是减少冲突、重复和不必要长期保留的信息，并把长期有效的规则放到合适的位置。

## 流程

1. 确认审查范围，包括系统规则、AGENTS.md、项目规则、Skills、references、Memory、工具描述、few-shot 和其他会进入上下文的资料。
2. 找出重复规则、相互冲突的要求、过时信息、适用范围错误，以及长期规则与任务临时信息混放等问题。
3. 判断内容应该继续长期保留、按需加载、移动到 references、由脚本或工具强制执行，还是删除。
4. 对每项建议说明当前问题、影响、建议位置和迁移风险；已有明确负责方的规则不要在其他位置重复定义。
5. 优先做最小调整，避免为了整理结构而重构整套提示词体系。

## 边界

这里只审查上下文组织和指令职责，不评价业务代码质量，也不负责重新设计完整 Agent 架构。涉及行为改变时必须指出影响范围，不能把减少上下文 token 消耗作为唯一目标。
