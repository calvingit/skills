# Verify

确认当前任务是否真的完成，以及是否有足够证据支持。重点回答“它是否按要求工作、证据是什么”，而不是评价代码质量或设计质量。

## 与 code-review 的边界

`verify` 只验证可观察结果和完成条件，不做代码规范、设计质量、代码异味、抽象合理性或实现风格审查；这些属于 `code-review`。

即使实现存在代码质量或设计问题，只要满足明确的完成条件且验证证据成立，`verify` 仍可判定验证通过；即使代码质量良好，只要关键行为未验证或验证失败，`verify` 就不能通过。

## 流程

1. 从用户要求、SPEC、ticket 或调用方提供的信息中提取可验证的完成条件；没有明确条件时，只验证能够客观确认的部分，不自行扩展需求。
2. 根据变更范围和风险选择最小必要验证：针对性测试、lint/typecheck、构建、运行时检查、接口调用、静态搜索、diff 或其他项目已有验证方式。
3. 优先复用仓库现有脚本、Make target、CI 命令和测试入口，不为了验证新增生产代码或测试专用接口。
4. 记录实际执行的命令、关键输出和失败项；无法执行的验证明确标为未验证，不能用代码阅读代替运行证据。
5. 对照完成条件逐项给出 `verified`、`failed` 或 `not_verified`，并说明证据。

## 边界

默认不修改产品代码来让验证通过。发现失败时报告失败现象和证据；需要定位运行时原因时交给 `debug`，需要评价代码质量或需求/HLD 实现质量时交给 `code-review`。
