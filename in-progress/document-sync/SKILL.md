# 文档同步

代码、配置或流程变化后，检查 README、项目文档、示例、图示和说明文件是否仍与实际情况一致。只修正已经过时的内容，不顺手改写无关部分。

## 流程

1. 先确认本次发生变化的事实，包括接口、配置、目录、职责、流程、术语、状态、示例或配图的具体变化。
2. 搜索描述或依赖这些内容的项目文档、示例、SVG、HTML、Mermaid、注释和说明文件。
3. 区分已经过时的内容与仍然成立的背景说明，只修改受当前变化影响的部分。
4. 检查跨文件术语、链接、路径、命令和流程图是否一致，避免正文已更新，示例或配图仍保留旧说法。
5. 修改后再次搜索旧术语、旧路径或旧行为，并说明仍无法确定是否需要更新的文档。

## 边界

`document-sync` 以已经确认的实现或规范事实为准，不负责创造新需求或技术设计。没有证据表明文档已经过时时，不为了统一风格而改写内容。
