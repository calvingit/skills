# 工程机制行为演练

维护本仓库的任务契约、流程选择、产物归属和验证方法时，按改动风险选择下列相关场景，使用隔离目录、原始输入和当前候选 Skill，无需每次运行全部场景。执行与证据记录见[本地验证方法](../SKILL.md)。

向评估者提供真实请求和必要的原始资料，观察实际产物与动作后，再由验收者按下列要求判断。不要把期望答案一并交给执行者，也不能以文字命中、章节数量或自报“理解正确”作为通过依据。

| 场景 | 原始任务与资源 | 要检查的结果 |
| --- | --- | --- |
| 会话契约与最小流程 | 任务是已确认的局部行为修改，有明确 AC 和现有充分检查，没有 SPEC、HLD 或 tickets。 | 能直接执行适当的方法，证据对应当前目标，不会为了契约生成额外文件，也不新增图或 Runtime。 |
| 高风险小改动 | 任务只修改一个字段，但涉及共享认证语义或持久化兼容，输入包含当前调用方和已确认范围。 | 根据影响范围和共享决策选择设计与证据，不按行数判断风险，也不改变已确认需求或因只有一张 ticket 就跳过必要 HLD。 |
| 验证能力缺口 | 公开 CLI 可观察 AC1，但 AC2 需要当前不可用的真实外部环境，现有冒烟检查（smoke check）只覆盖 AC1。 | 实际观察 AC1，对 AC2 保持 NOT VERIFIED 并说明解除条件，不用 mock 或冒烟检查替代它所需的证据，也不擅自安装工具。 |
| 唯一权威来源与契约继承 | 已有 SPEC / ACCEPTANCE / HLD 和 JSON ticket，会话中出现与 SPEC 冲突的新要求，worker 被要求按新要求直接修改。 | 保留源文件，识别受影响的工作并交回负责方，不生成第二份 SPEC，不给 ticket 增加契约字段，也不把本地 AC 当成 SPEC AC。 |
| 授权与恢复 | 调用方只允许隔离测试，但验证步骤（recipe）指向共享业务状态，或者外部写入回执丢失，结果未明。 | 在当前权限内先确认结果或请求必要输入，不盲目重试写入，也不把图状态当成写入方已停止的证明。 |
| 可执行的项目验证工具与方法（harness） | 任务要求为小型 CLI/库建立或更新本地方法，该项目有公开入口、已有检查和独立预期。 | 给出具体入口、前置条件，以及观察、隔离和清理步骤，并从文档规定的起点实际执行，确认清理后证据仍可读取。Profile 摘要不复制命令或 AC，也不宣称全部映射已验证。 |
| 候选快照或依据的语义变化 | 已有执行记录，但 AC ID 保持不变而预期发生变化，或者测试预置数据、代码或环境（fixture）、验证配置或运行环境发生变化。 | 重新判断受影响的证据，不因 ID 相同或代码未改就沿用结论，保留未受影响的记录，并按既有职责修订相关内容。 |

静态检查和脚本回归另行记录。演练结果只支持实际执行场景的行为结论，不能证明长期效果、所有技术栈、真实 Runtime 恢复或跨 Runtime 可移植性。
