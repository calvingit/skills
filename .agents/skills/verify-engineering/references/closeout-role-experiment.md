# 收尾角色对照实验

用真实任务比较两种收尾策略，决定固定三角色收尾是否可以改为按风险选择角色。当前只建立可重复实验；在取得支持变更的证据并经仓库正常评审前，quick-implement 与 Loop 的既有收尾要求不变，本实验不是变更授权。记录纪律沿用 [Retro 实验规范](retro-evaluation.md)：真实 session 证据、脱敏、不凭感觉估算指标。

## 对照组

| 组 | 策略 | 定义 |
| --- | --- | --- |
| A（现行） | 固定三角色 | 按当前契约执行全量收尾：`simplify`（Review 模式）→ `verify`（逐 AC）→ `code-review`（改动集），各自独立角色上下文 |
| B（候选） | 按风险选择 | 按流程选择的三维（不确定性、影响范围、验证难度）在任务开始前预先登记将运行哪些收尾角色及依据；登记后不得事后增补理由 |

B 组必须**预注册**角色选择：在看到收尾结果前写下选择的角色、放弃的角色和判定依据。未预注册的 B 组样本无效——否则"按风险选择"会退化成"按结果选择"，实验失去意义。

## 任务类型

每类任务在 A、B 两组各至少运行 3 个真实任务（不同候选、不同仓库状态）；结果方向不一致时增加样本，不以单次结果下结论。

| 类型 | 定义 | 重点观察 |
| --- | --- | --- |
| 局部改动 | 单模块行为变更，不动共享契约 | 低风险任务上固定角色的边际成本 |
| 共享契约改动 | 改动共享类型、接口、状态/错误语义，跨模块或跨调用方 | B 组缩减角色后是否漏掉跨调用方回归 |
| GUI 任务 | 用户可见 UI 行为，需要视觉或交互证据 | 验证缺口、视觉证据充分性 |

同类型任务尽量同题材配对（A、B 跑同一需求的不同实现，或同一改动在两个隔离仓库状态上各跑一次），并记录模型、Runtime 与候选版本。无法配对时注明比较限制。

## 度量

| 指标 | 定义 | 来源 |
| --- | --- | --- |
| 漏检率 | 交付候选中实际存在、但该组收尾未报告的缺陷数 ÷ 事后审计确认的缺陷总数，按严重性分层 | 事后独立审计（见下） |
| 错误结论率 | 与基准事实矛盾的判断数 ÷ 判断总数：错误的 PASS、把环境问题当产品缺陷、把未验证写成通过 | 基准事实（见下） |
| 耗时 | 从收尾开始到最终判定的墙钟时间，及角色调用次数 | 记录的时间戳，不估算 |
| 成本 | 工具/模型调用数、token 或执行预算 | Runtime/模型记录，缺失时如实注明 |

另记加载与执行证据：每个被派发的角色是否实际加载了对应 Skill、是否产出原始报告（派发成功不等于判断发生）。这本身是被测策略的一部分，不作为独立指标。

## 基准事实

漏检率与错误结论率需要独立于 A/B 两组的基准事实，二选一并记录：

1. **种子缺陷**：在收尾开始前向候选植入已知缺陷清单（含跨调用方回归、条件分支、映射错误各至少一类），收尾后核对哪些被报告。
2. **事后独立审计**：由未参与 A/B 任何一组执行的更强审查（如 2–3 名独立审查者对同一候选全文审查）确认缺陷全集。

只用实现者自检或单一审查报告作基准的样本，只能报告错误结论率，不得报告漏检率。

## 判定条件

同时满足以下条件，才提出将收尾策略改为按风险选择的建议（仍是建议，由维护者评审决定）：

1. 三类任务合计，B 组漏检率与错误结论率不高于 A 组，且无任何一类任务中 B 组出现 A 组没有的严重漏检。
2. B 组耗时或成本有可观察、可复现的降低，不是单次波动。
3. B 组预注册的角色选择依据可解释：被放弃的角色对应的风险维度确实低，而不是习惯性缩减。
4. 结果方向在同类多个任务上一致；模型或环境差异较大时注明比较限制。

任一条件不满足时维持固定三角色。即使全部满足，共享契约改动的收尾角色缩减仍需单独证据，不随总体结论自动放宽。

## 输出与路由

实验输出只包含各组度量、基准事实方法、样本清单、比较限制和建议；放入调用方指定的证据目录，脱敏后使用，不写入稳定 Profile 或产品快照。据此提出的策略变更走仓库正常评审；实现缺陷、验证方法缺口分别交 `code-review`/`simplify` 与 `verification-setup`，原生 worker 生命周期问题交 Runtime 维护者。
