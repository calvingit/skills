# Task Decomposition

仅在实现跨多个 fresh context 或存在真实 blocking edge 时使用。

- 每个 task unit 交付一个可观察或可验证的完整结果，使用稳定 `T` ID。
- 只记录真实依赖；无 blocker 的 task 可以开始，不为形成线性顺序制造依赖。
- 每个 task 至少覆盖一个 `AC`，全部 `AC` 必须被覆盖。
- task 只能细化已确认决策；发现新产品、协议、边界或验收选择时回到分析阶段。
- 测试、静态检查、文档收尾和清理默认属于对应 slice，不单独制造 task。
- 每个 task 只写交付结果、Blocked by、AC、必须保持和验证目标；禁止文件清单、代码片段、命令和实现步骤。

自检：完成后是否能说明外部可观察结果、依赖确实阻塞、AC 映射完整，且实现 Agent 仍需基于当前仓库重新调查。
