# Engineering Skills 职责与边界

本轮以现有 Engineering Skills 为范围，检查职责、写入产物和结论依据。暂不新增全局 Skill、通用编排层或 Runtime；优先组合已有能力和项目方法。项目本地验证入口属于项目知识，不等于扩张全局 Skill 数量。解冻需有真实任务中的能力缺口及无法通过现有职责解决的依据。

## 三个边界

| 边界 | 必须能回答的问题 | 处理方式 |
| --- | --- | --- |
| Scope | 处理什么目标，可以修改什么？ | 区分预期修改区域、角色写权限和 Runtime sandbox；不要将所有任务范围都变成硬文件白名单。 |
| Decision | 哪些选择可自行决定，何时交还责任方？ | 普通实现由 Agent 判断；行为和验收回到需求，共享设计回到 HLD，执行图拆分回到 to-tickets。 |
| Evidence | 哪些来源和观察足以支持本角色的结论？ | 区分意图、当前行为、设计判断和实际验收，不以自报、绿色命令或其他角色的结论替代证据。 |

以下是维护者审计表，不要求每个 Skill 复制同一套章节或加载整张表。执行规则以各 Skill 为准；同一份测试或代码可用于不同判断，重复调查对象不等于职责重复。

## 职责审计

| Skill | 范围及可修改产物 | 决策与停止点 | 结论依据 |
| --- | --- | --- | --- |
| project-setup | 稳定 Profile、AGENTS.md 入口及获准迁移 | 固化已确认配置；不建 harness、不决定验收 | 项目已有约定、源文件及用户选择 |
| verification-setup | 本地验证方法、必要辅助脚本、验证导航和摘要 | 创建/刷新并试运行方法；依赖、CI、产品变更另交实现 | 实际启动、驱动、观察、清理与保留证据 |
| improve-agents-md | 获准的项目指令修改 | 判断指令是否有依据；不自行重配 Profile | 仓库规则、真实命令与适用范围 |
| find-docs | 只读文档检索 | 回答指定产品/版本的问题；不开展完整选型 | 官方资料、明确版本、未执行限制 |
| tech-research | 有边界的技术调研 | 提供推荐和采用条件；不直接实施 | 官方/工程资料、现状约束、已执行实验与推断区分 |
| grilling | 访谈及 decisions.md；组合记录术语/ADR | 用户决定重要需求选择；不决定局部实现或重写下游 | 当前事实、用户确认、未决 frontier |
| wayfinding | MAP.md 与决策文件 | 解决跨会话依赖决策；不交付产品 | 可追溯答案、调查或实验；HITL 不由 Agent 代答 |
| to-spec | SPEC、按需 ACCEPTANCE | 维护确认需求和验收语义；不设计内部实现 | 需求 authority、确认决策、外部契约 |
| high-level-design | HLD | 决定共享设计；长期方向经 review gate；不改需求或拆票 | SPEC、真实调用方、项目约束和代码事实 |
| to-tickets | 通过脚本创建/协调 tickets | 决定交付拆分与真实依赖；不引入新需求/设计 | 已确认 SPEC/HLD、覆盖及图校验 |
| quick-implement | 单一目标实现、自检与收尾 | 无执行图；既有独立收尾规则仍适用 | 当前契约、真实 diff、自检与独立报告 |
| implement | 当前 ticket 的代码、必要测试和局部简化 | 决定局部实现；契约问题交回调用方 | 已确认行为、项目方法和实际本地检查 |
| loop | attempt、状态、报告及交付记录 | 选工作、调用角色、判断结果、流转状态；不管理 Runtime | 全部相关 AC 证据、原始报告、有效候选快照 |
| verify | 只读验收；获准隔离资源中的探针/证据 | 逐条 PASS / FAIL / NOT VERIFIED；不修复或改状态 | 需求独立预期、可观察执行、证据可信度与覆盖限制 |
| code-review | 只读改动审查 | 找具体缺陷、回归和无必要复杂度；不代替逐条验收 | 可达场景、调用/保护/测试与反证 |
| test-audit | 指定测试审计；获准时限定清理 | 保留/合并/重写/删除建议；不成为固定交付门 | 独立预期、真实执行、独有保护与维护成本 |
| tdd | 实现中的行为测试、代码及局部重构 | Red → Green → Refactor；不拥有最终验收或任务调度 | 已实际运行的有效 Red/Green、独立预期与回归 |
| codebase-design | 指定 Module / Interface / Seam 的局部设计判断 | 推荐局部形状；不扫描整体架构或替代领域语言 | 真实调用、信息隐藏、变化原因与删除试验 |
| domain-modeling | 领域词汇与符合门槛的 ADR | 澄清模型，记录确认语义；不拥有访谈节奏或改需求 | 当前领域约定、契约、确认术语及真实取舍 |
| review-architecture | 只读架构审查；显式候选发现 | 判断现状与影响；不预先实施目标架构 | 项目约束、路径/所有权、适用官方指导与反证 |
| simplify | Review 或获准的限定修改 | 删除无当前职责的复杂度；不改变确认行为 | 真实消费者、持久化/外部契约与修改后验证 |
| debug | 复现、诊断；获准的最小修复 | 先建立问题反馈；不扩大到架构重做 | 已运行的症状复现、可证伪假设及原复现回归 |
| challenge | 只读地挑战已有判断 | 检验结论；不扩成需求访谈或完整重设计 | 已有约束、反证、影响及尚未确认事实 |
| how | 手动触发的当前代码解释 | 回答如何运行；不追溯历史或提出目标设计 | 当前真实生产路径与明确未观察范围 |
| why | 手动触发的历史依据调查 | 区分事实、推断、假设和未知；不因历史证明现状正确 | Git/ADR/issue 等历史与当前代码的关联 |
| fuck-my-shit-mountain | 显式项目审计、综合报告 | 负责选定维度覆盖；不自动修复或启动交付链 | 各维度证据、可达影响、反证及覆盖限制 |

## 本轮处理的重叠和越界

- Profile 字段语义、读取和迁移集中在 project-setup 的[引用说明](../engineering/project-setup/references/profile.md)。消费者读相关设置，不绑定 AGENTS.md 内嵌格式；保留旧持久化配置直到获准迁移。
- verification-setup 维护方法和能力摘要，verify 判断当前 AC 的充分证据。没有另一套验证命令配置或强制工具选择。
- verify 保留当前证据可信度检查；test-audit 保留系统测试价值审计；code-review 保留改动风险判断。不让任何一个报告替代另一个角色的验收责任。
- implement 已负责当前变化造成的必要简化，simplify 检查仍存在且有证据的问题。Loop 保留已有最终 simplify 角色契约，不新增逐 ticket 审计。
- Loop 删除固定无活动阈值、soft-ping 协议、活动时间及性能台账；不再要求固定 context 文件对。原生 worker 执行、独立最终角色、证据失效重验和停止旧 writer 的要求保留。
- codebase-design 的分析术语限定在设计讨论中，不要求项目把 service/API 等既有名称改成通用词汇。
- 其他现有入口有不同的判断目标和停止点，本轮保留；不因检查同一份代码就合并。

## 验证边界

图、attempt、事务和交付快照由现有 `python3 engineering/shared/check.py` 检查。Profile 迁移、按需读取及验收证据选择另用隔离任务演练；审阅文档不证明 Runtime 生命周期、真实项目 GUI 质量、长期 token 或耗时改善。这些效果需后续真实任务记录支持。
