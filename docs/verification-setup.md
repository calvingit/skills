# 项目验证配置与维护

`verification-setup` 回答“这个项目怎样取得可复核的验证证据”。它先调查仓库，复用已有工具，创建或刷新项目本地验证 Skill，再实际执行生成的步骤。它不声明当前功能已经验收通过。

## 职责与入口

| 入口 | 职责 |
| --- | --- |
| `project-setup` | 发现并维护 `verification_instructions` 等稳定入口，缺少验证方法时建议使用 `verification-setup`。 |
| `verification-setup` | 调查运行条件、可驱动接口、观察方式和隔离能力，维护项目验证方法。 |
| 项目本地验证 Skill | 提供具体的检查选择、准备、运行、证据保留与清理步骤。 |
| `verify` | 独立地逐条判断 AC，返回 `PASS / FAIL / NOT VERIFIED`。 |
| `loop` | 消费结果，决定修正、阻塞或完成；验证缺口不直接当成产品缺陷。 |

不要求每个仓库先配置 Profile 或生成验证 Skill。已有文档和脚本足够时直接使用；需要把这些知识整理成可重复执行的入口时，再调用 setup。已有入口发生变化时再次调用同一个 Skill 增量维护，无需另建 maintain Skill。

## 如何使用

- 首次建立：`使用 verification-setup 分析这个仓库，复用已有验证工具，为当前产品建立项目本地验证 Skill，并实际跑通一条代表性路径。`
- 更新现有方法：`使用 verification-setup 更新 API 的验证入口，检查启动命令和测试数据隔离方式，保留现有 Web 验证方法。`
- 多端项目：`检查 mobile、web 和 api 的验证入口，以及登录流程跨端的证据缺口。只在执行方法不同的地方拆分 Skill。`

默认位置是 `.agents/skills/verify-<surface>/`，已有项目约定优先。一个执行方法共用的项目通常只需要一个 Skill；多端有不同运行或隔离方法时可以分别维护，并用一个索引说明各入口和跨端流程。`verification_instructions` 指向单个 Skill 或这个索引，不再增加一组 Profile 字段。

## 生成什么

| 内容 | 必须回答的问题 |
| --- | --- |
| 检查选择 | 每种检查能证明什么，成本和前置条件是什么，哪些项目门禁必须执行？ |
| 准备和环境检查 | 在哪里执行，用哪个版本，如何确认正确的实例或构建已就绪？ |
| 驱动和观察 | 通过什么公共接口操作，预期结果和副作用在哪里观察？ |
| 隔离和清理 | 测试可修改哪些隔离资源，如何避免占用共享会话，失败后如何清理？ |
| 证据 | 保存动作、结果、实际命令、退出码、环境和候选版本到哪里，清理后是否仍可读取？ |
| 能力映射 | 哪个领域功能对应哪种方法，依据来自哪里，哪些路径或平台尚未覆盖？ |

小项目可以全部写在 SKILL.md；功能较多时再拆出被引用的说明。已有命令和测试仍是执行入口，不为了统一接口再造 runner。功能映射帮助导航，不复制 SPEC，也不从现有实现反向定义需求。

工具由需要观察的行为决定。例如原生权限操作可能需要现有移动端驱动能力；如果仓库只有组件测试，就明确这部分缺口，不能把组件测试绿色写成原生流程已验证。新增依赖、CI 或产品测试能力属于另行处理的实现工作，不因识别到 Flutter 就安装 Patrol，也不因识别到 Web 就安装 Playwright。

## 可用性的证明与限制

每种新建或改动的执行方法至少跑一条代表性路径：前置检查、必要的启动、公共接口操作、结果观察、证据保留、清理，再确认产物仍在。库和短生命周期 CLI 无需引入常驻服务。

报告分别说明已写入的方法和实际执行的覆盖。环境不可用或执行失败时，受影响的方法保留为明确标注的草稿，并说明阻塞解除条件或所需修复；不能宣称已可用。一个方法通过也不能替另一个失败或未执行的方法背书。

冒烟运行证明该执行方法在记录的环境中可运行，不证明全部功能或当前任务 AC 已通过。独立验收继续由 [verify](./verify.md) 完成。视觉符合性、交互体验、真实第三方集成等也只能在对应证据实际存在时确认。

## 设计来源

借鉴 pstack 的 [create-verification-skill](https://github.com/cursor/plugins/blob/main/pstack/skills/create-verification-skill/SKILL.md)：先从仓库查明运行、驱动、观察和隔离方法，生成本地技能后实际试运行，并在清理后保留证据。本仓库将创建和维护合在一个入口，沿用 `.agents/skills` 和已有 Profile，支持多端导航，保留全局 `verify` 的独立证据判断，不强制工具或测试层级。

执行规则见 [`engineering/verification-setup/SKILL.md`](../engineering/verification-setup/SKILL.md)；生成内容的职责见[项目 harness 契约](../engineering/verification-setup/references/project-harness.md)。
