# 后端 Skills 行为评估

用于维护 Skills 时评估决策质量，不是日常后端任务的必经检查。以下是可复用场景，尚未执行行为对比，不能据此声称 Skill 已改善实际效果。

## 运行方式

选择与本次 Skill 修改相关的场景，准备可运行的隔离仓库或脱敏证据。固定任务、初始文件、模型、工具和权限，分别在无该 Skill 与加载该 Skill 的新上下文中执行。已有通用工程指令保持一致；记录实际加载的技能，避免基线通过自动路由意外加载待测 Skill。

给执行者任务和原始材料，不提供下面的判定要点。只读场景不授予写入权限，外部系统使用本地替身，不连接生产。比较原始报告、文件差异和运行结果；同一条件下有多次样本时保留差异，不用一次通过证明稳定有效。

## 场景

| 场景与任务 | 最少原始材料 | 评估者判定要点 |
| --- | --- | --- |
| 普通 CRUD：沿用现有接口增加一个查询筛选项 | 路由、授权、查询实现、分页约定及现有测试 | 保留授权和结果上限；改动与需求对应；没有无依据地增加缓存、中间件或架构层次 |
| 外部写入超时：修复偶发重复扣减 | 本地 provider 替身在提交效果后丢弃首次响应，提供已有操作标识及查询接口 | 没有把超时等同于未执行；重试保留操作身份；最终业务效果和返回结果均可核对 |
| 并发状态更新：修复两个请求同时领取同一资源 | 真实持久化边界、唯一领取约束、可控制的并发入口 | 两个请求竞争时仍满足约束；没有只做先查后写或仅靠单进程锁掩盖跨实例问题 |
| 回填中断：让现有脚本安全续跑 | 分批脚本、旧数据、新业务写入入口及可注入中断点 | 检查点不越过未提交数据；重复批次不破坏结果；中途的新写入没有被覆盖或遗漏；说明旧版本能否读取新数据 |
| Worker 退出：修复部署期间丢失任务 | 消费者、确认时机、重投配置和终止窗口 | 停止领取、完成或回收在途任务的行为可观察；不把进程退出当作任务成功；检查副作用与确认之间的故障窗口 |
| 依赖变慢：分析排队与重试造成的请求堆积 | 有限连接池、队列配置、嵌套重试设置及本地延迟替身 | 能联系并发、队列和重试总量；没有直接扩大连接数或无限排队；区分证据与容量假设 |
| MySQL 局部诊断：仅分析一条查询为何变慢 | 版本、表与索引、计划、数据分布及同窗口指标 | 保持只读；从相关证据开始，证据不足时才扩大调查；没有从 SQL 文本直接建议加索引或执行变更 |

## 记录结果

每次保留场景、Skill 修订版本、环境与加载上下文、原始输出、实际命令和可观察结果。分别记录关键遗漏、无依据设计、无关检查、授权越界和无法验证的部分，并注明证据位置。

格式、链接或单元测试通过只证明对应静态或脚本检查通过。只有实际执行上述任务并比较结果，才能报告行为评估结论；没有运行的场景明确记为未执行。
