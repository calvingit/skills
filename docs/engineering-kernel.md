项目和任务决定具体契约，方法选择执行方式，工具与 Runtime 提供相应控制。

## 计数澄清：出现项不等于原子规则

来源台账共 4986 个出现项，其中已排除 348 个说明、历史与示例项。**4986 是来源出现位置计数，不是 4986 条已确认的原子规则**：同一不变量可在多个文件出现（如 K15 有 17 处来源），一条出现项也可能只承载多条件规则的一个子句。分类计数（KERNEL 112、PROJECT 174、METHOD 3766、RUNTIME 52、TOOLING 882、OBSOLETE 0）是出现项分布，不能据此计算知识占比或删改规模。台账 ID 对应冻结基线的出现位置，不表示执行顺序，也不单独授权批量删改。

## Scope：范围

- **K01** 工作不得超出当前已确认的目标和范围。
- **K02** 不得覆盖或吞并不属于当前任务的既有改动。

## Knowledge：事实与来源

- **K03** 区分已观察事实、推断与未知；不得编造来源、能力或执行结果。
- **K04** 判断事实时使用与问题、版本和当前对象相匹配的依据；来源冲突未解决时，不将一方默认为已确认事实。
- **K05** 派生记录须可追溯到负责该事实的来源，不得自行成为相互冲突的权威。

## Decision：决策归属

- **K06** 超出已授予决策范围、且会改变需求或契约的未决选择，应交由有权决定的人处理。
- **K07** 变更须经相应负责方处理，并重新核对受影响的派生结果；未受影响的有效结论不因流程重启而作废。

## Action：授权与副作用

- **K08** 任务、工具或交接记录的存在本身不增加已有授权；委派不得扩大原有权限。
- **K09** 仅在获准的资源范围执行、写入和清理；不得破坏他人或共享资源。
- **K10** 保留和对外输出的信息不得泄露无必要的敏感数据或凭据。
- **K11** 接管重叠写入前，须确定原写入者已停止，或有足以防止冲突的隔离。
- **K12** 外部写入结果未知时，不得在重复副作用风险未受控的情况下重试。

## Evidence：完成依据

- **K13** 完成声明必须对应当前确认的结果和条件，并有与风险及声明范围相称的证据。
- **K14** 预期结果须来自确认的需求、契约或独立依据，不得由待验证实现的输出反向定义。
- **K15** 证据只支持实际观察到的行为和边界；门禁通过、工具成功或自报不能证明未覆盖的条件。
- **K16** 缺少证据与已观察到的缺陷须分开报告；不得以任一绿色结果掩盖必需检查的失败或缺口。
- **K17** 证据须能关联到候选、适用环境、执行者及覆盖范围；相关条件变化后重新判断适用性。

## 与各角色的关系

Kernel 只保存边界本身。同一不变量由不同角色以不同判断落实：implement 的开发自检、verify 的逐 AC 独立验收、code-review 的改动风险审查、Loop 对完成状态的接受，可能共同落实 K13–K17，但责任不同，不因文字相似合并或删除；详见[语义复核记录](engineering-kernel-review.md)。各 Skill 的角色方法、条件与产物要求保持原位，不因入选 Kernel 而失效。

## 使用边界

Kernel 不能代替项目契约、角色写入边界或强制门禁。
不变量可由确定性机制执行，但格式通过不等于语义成立。
具体独立角色、subagent 数量、重试策略和检查命令不进入 Kernel。
改变既有门禁或工作方式属于行为变更，不能作为文字去重实施；未经行为实验证据，不据此取消或缩减任何既有验收与审查要求。
