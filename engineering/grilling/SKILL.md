# Grilling

在实现前把需求或预期行为变更中的未决决策收敛为用户确认的选择。只做调查、提问和收敛；不写代码，不生成 SPEC/PLAN 等正式文档。

## 1. 命名 Destination 并查明事实

先用一两句话命名 **Destination**：任务完成后应成立的状态。Destination 同时约束完成条件和范围。

按相关性调查当前工作区、项目指令、领域词汇、长期决策、历史任务文档，以及与决策相关的代码、调用链、数据流、接口、测试和配置。不要假定这些资料存在于固定路径；先发现当前仓库自己的约定。

- Destination 明确包含架构调整、模块深化、解耦、公共 Interface 或可测试性时，调用或参考 `codebase-design` skill 的共享设计纪律，调查当前生产调用方、测试调用方、composition root、real Adapter，并把“小而稳定的生产 Interface、生产与测试同路径、必须保留的必要复杂度”转成可判定的质量属性。不要把“解耦”默认解释为增加回调、DI 容器或新抽象。
- 先搜索发现，不假设固定路径、技术栈或文档一定存在；优先遵循用户明确约定，其次遵循当前项目约定。
- 能够自行查明的事实不询问用户；来源冲突时指出冲突并确定权威来源。
- 提问前还原隐含需求：逐项确认触发条件、data gate、权限、空态/失败/取消路径、生命周期/并发、兼容性和既有调用方约束。每条验收必须能追溯到用户确认、权威文档、公开 contract、生产调用链或既有测试；无法追溯的内容标为推断或阻塞决策，不得直接写成需求。
- 用外部可观察结果表达成功条件；对每条成功条件逼问一次“怎么算成”。无法在不引用实现细节的情况下判定成立时继续收敛，不留模糊验收进入落盘。期望值必须有独立来源，例如用户确认、权威文档、既有契约或 worked example；给不出独立来源时继续作为未决决策。

## 2. Design Tree 与 frontier

把会改变方案的决策建成 **Design Tree**，并标明每个决策依赖的事实或上游决策。

- **frontier** 是前置条件已解决、当前可以询问的决策集合。
- 每个 **round** 一次批量提出整个 frontier。
- 依赖本 round 答案的问题留到下一 round。
- 依赖未查明事实的问题保持锁定，先调查，不猜测补全；不依赖该事实的 frontier 问题仍在当前 round 照常提出。

只按答案依赖计算 frontier，不按业务流程顺序、叙述顺序、主题分类或问题数量拆分 round。构造每个 round 前，逐个检查所有候选问题：

1. 该问题的候选方案或推荐答案是否会随另一个未确认决策的答案而变化？
2. 该问题是否依赖尚未查明的项目事实？

两项均为否时，该问题必须进入当前 frontier。业务处理的先后顺序不等于决策依赖。

## 3. 候选方案

为每个真正的决策列出会实质改变契约或方案的主要候选，不只给推荐答案，也不为凑数量制造伪选项：

- 候选互斥时标为单选，使用 A、B、C 编号。
- 候选允许组合时标为多选，说明最少、最多或互斥约束，并给出推荐组合。
- 多选只用于同一决策内可兼容的能力或行为；彼此独立、各自改变不同分支的事项应拆成多个问题，并留在同一 frontier 批量提出。
- 已被事实、既有契约或用户明确要求排除的方案不作为候选；只剩一个可行答案时，将其记为已确认事实或默认假设，不为展示流程而提问。
- 允许用户给出候选之外的答案。

每题包含：编号、会改变方案的具体问题、单选/多选、主要候选、推荐答案及理由、可验证依据、已满足的依赖关系。

## 4. 回答处理与收敛

用户回答后记录已选方案、放弃的主要替代方案及原因、默认假设，再重算 frontier。答案暴露的新决策进入后续 round。

当以下条件全部成立时汇总收敛结果并请求用户确认：

- 没有阻塞性未决决策。
- 已确认方案、放弃方案和默认假设均已记录。
- 实际存在的非阻塞事项已有当前默认行为、不阻塞原因和重新决策条件。
- 高层任务边界清晰，足以支撑后续文档生成。

收敛后建议用户调用 `to-spec` skill 落盘生成 SPEC.md 与 PLAN.md；Grilling 的问答只保留在当前会话，不生成文件。

## 边界

- 调查发现重要路径已超出当前会话能看清的范围（Fog of war），或决策工作无法在当前会话完成时，说明升级依据并取得用户确认后，建议使用 `wayfinding`。
- 实际行为违反已有权威来源明确规定的 expected behavior 时，这是 bug：停止本流程，建议使用 `debug`。
- expected behavior 本身尚未确定时，仍属于本 skill 的收敛范围，不要伪装成 bug。
- 对话和解释沿用用户语言；Destination、frontier、round 等 canonical term 首次出现时直接解释含义，不创造额外术语体系。
