# 连接与运行

## 连接与超时

核对驱动及 ORM 的客户端生命周期、池配置与监控；按驱动约定复用客户端，避免每请求新建。区分服务器选择（server selection）、连接建立、连接池等待、套接字（socket）与整体操作超时。

计算容量时考虑进程、实例、副本或路由节点及扩容峰值；池与监控连接数量按实际驱动和拓扑判断，不套用通用的“每个连接占用多少内存”估算或固定池大小公式。池等待高时先检查慢查询、事务与应用并发，不直接增大 maxPoolSize。

## 现场诊断

按症状选择证据：应用等待与驱动事件、慢查询、已有 profiler 数据、服务器负载、复制延迟或存储。比较同一时间窗口；无 Atlas 或 MCP 时可用脱敏日志、计划和配置，不因此中止所有分析，也不编造监控结果。

检查应用超时后服务器端工作是否仍在执行。查看当前正在执行的操作时，应限制所用权限并保护敏感输出；终止操作、开启 profiler 或修改采样配置属于有副作用的动作。

## 运行变更

索引构建、删除、验证器调整、批量修复、分片或恢复前，明确目标集合、版本与拓扑、影响范围、磁盘与负载余量、停止条件和恢复方式。新建唯一索引前核对历史冲突；回退配置不等于撤销已修改的数据。

备份恢复要在隔离的目标环境中验证，核对数据与应用行为，再按授权切换流量。分片键、重新分片（resharding）和跨分片唯一性等决策需要对应版本专项调查，不凭数据量大就建议分片。

核对网络边界、TLS、最小权限、租户隔离和输出脱敏；不要为连通性关闭认证或开放网络访问。连接 URI、查询样本和执行计划可能包含凭证或业务数据。
