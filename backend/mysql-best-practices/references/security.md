# MySQL 安全规范

用于审查连接、身份、权限、查询构造、敏感数据、数据库对象和备份恢复风险。

## 查询与输入

- 参数值使用预编译语句或参数绑定，不使用字符串拼接。
- 表名、列名、排序方向等无法作为普通参数绑定的结构片段，必须由服务端映射到有限的允许列表；无法安全映射时应重构查询。
- 参数化只能防止语法注入，不能替代业务授权。多租户查询需要从可信上下文确定租户范围，并用数据库约束保护关键唯一性。
- 动态查询生成器、ORM 原生 SQL、报表筛选、导入任务和运维脚本同样需要防范注入。

## 身份与权限

- 运行时、只读分析、迁移、备份和管理账号应分开，按实际对象和操作授予最小权限；应用不能使用管理员账号或共享的个人账号。
- 凭据放入受控的密钥系统并支持轮换和吊销，不能写入仓库、镜像、命令历史、工单或诊断输出。
- 定期审查闲置账号、通配 host、匿名账号、过期授权和高风险全局权限。
- 审查 view、procedure、function、trigger、event 的 `DEFINER` 和执行上下文，避免对象迁移后发生权限提升或引用已经失效的账号。
- 权限变更前先证明调用路径确实需要，不能用“先给大权限再说”代替诊断。

## 连接与传输

远程连接使用加密协议，并在客户端或平台支持时验证服务端身份和主机名。只开启 TLS 而不验证证书，仍可能无法抵御中间人攻击。还需核实云平台的证书轮换和客户端信任链。

网络隔离、私网、堡垒机和安全组属于纵深防御，不能替代数据库认证和最小权限。管理端口不应向不受信任的网络开放。

## 日志、监控与诊断

- 慢日志、general log、审计日志、Performance Schema、错误日志和 APM 可能包含 SQL、参数、账号和业务标识；应限制访问权限、保留期限和导出范围。
- 分享 `SHOW PROCESSLIST`、死锁、事务或 digest 输出前，对字面量、个人信息、令牌和业务标识进行脱敏。
- 排查问题时不要要求用户粘贴口令或完整连接串，使用占位符描述所需字段。
- 启用数据量较大的日志前，评估磁盘、I/O、隐私和计划关闭时间，事故处理完成后恢复原配置。

## 数据与恢复

- 敏感数据的静态加密、字段级保护、掩码和密钥托管应符合实际威胁模型与合规要求。
- 备份和 binlog 的敏感级别与生产数据相同；应限制访问、加密并校验保留情况，同时定期执行恢复演练。
- 删除或匿名化要求应覆盖副本、备份、搜索索引、缓存和分析链路，并明确法律规定的保留期限。
