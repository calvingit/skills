# Java 编程规约

> 基线：阿里巴巴 Java 开发手册（黄山版）。本文件用于 Agent 按需检索，不替代项目自身规范，也不追求逐字复制原手册。

## 命名

- 类名使用 UpperCamelCase；方法、参数、成员变量和局部变量使用 lowerCamelCase。
- 常量使用大写单词并以下划线分隔。
- 包名使用小写单词，避免无意义缩写和难以理解的自造缩写。
- 命名应表达业务含义；避免仅靠类型、序号或模糊词区分对象。
- 抽象类、异常类、测试类等遵循项目已有一致命名方式。

## 常量与字面量

- 不在业务逻辑中散落具有业务含义的 magic value；提取为有语义的常量或配置。
- `long` 字面量优先使用大写 `L`，避免与数字 `1` 混淆。
- 不用一个常量承载多个不相关语义。

## 面向对象

- 通过对象引用访问 static 成员会弱化语义，应直接通过类名访问。
- 覆写方法使用 `@Override`。
- 比较包装类型时注意对象比较与值比较的区别，不依赖缓存区间等实现细节。
- `equals` / `hashCode` 必须满足其契约；作为 Map key 或 Set 元素的对象尤其需要检查。
- 返回集合或数组时明确可变性，不暴露不应被调用方修改的内部状态。
- 构造对象时保持必要的不变量；不要依赖调用方按隐含顺序补齐对象状态。

## 集合

- 根据访问模式选择集合，不仅按习惯使用 `ArrayList` / `HashMap`。
- 创建容量可预估的集合时给出合理初始容量，避免明显的重复扩容。
- 遍历 Map 时根据实际需要使用 `entrySet`、`keySet` 或相应 API，避免重复查找。
- 不在 foreach 遍历中直接进行会破坏迭代器状态的结构性修改；需要删除时使用安全的迭代方式或集合 API。
- 使用 `subList`、`Arrays.asList` 等视图或适配结果时，先确认其可变性和与原集合的关联关系。
- 集合作为返回值或共享状态时，明确 null 与 empty 的语义，优先保持项目既有约定一致。

## 并发

- 明确共享可变状态及其同步策略；不要假设普通集合或普通字段天然具备线程安全性。
- 线程池应有明确的线程数、队列、拒绝策略和线程命名；避免隐藏资源边界的无界增长。
- `ThreadLocal` 使用后按生命周期清理，特别是线程池线程。
- 加锁范围保持必要且清晰；避免在锁内执行不可控的远程调用或长耗时操作。
- 使用并发容器、原子类、锁或同步机制时，以实际并发语义为依据，不机械替换。

## 控制语句

- 复杂条件先提炼业务语义，避免难以审查的长布尔表达式。
- `switch`、循环、提前返回等写法优先服从项目现有风格，但必须保证边界和 fall-through 意图清楚。
- 对外部输入、集合边界、可空值和状态枚举进行必要校验；不要用大量防御式分支掩盖模型设计问题。

## 代码格式

- 优先服从仓库已有 formatter、Checkstyle、Spotless、IDE 配置等自动化规则。
- 保持缩进、空格、换行、花括号与相邻代码一致，不为个人偏好制造无关 diff。
- 单行过长、链式调用或复杂泛型影响可读性时再合理换行。

## 注释

- 注释解释业务原因、约束、边界或反直觉行为，不重复代码字面含义。
- 公共 API 是否要求 Javadoc 以项目规范为准。
- 修改代码后同步更新已经失真的注释；不要保留与实现矛盾的历史说明。
- TODO/FIXME 应能说明待处理事项；项目有 issue/ticket 关联规范时遵循项目要求。
