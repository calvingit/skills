# Java 工程规约

> 基线：阿里巴巴 Java 开发手册（黄山版）。用于异常、日志、测试和安全相关任务的按需检查。

## 异常处理

- 异常用于异常流程，不用异常替代正常分支控制。
- 捕获异常后必须有明确处理目的：恢复、转换、补充上下文或在合适边界记录；不要静默吞掉异常。
- 不无差别捕获 `Throwable` 或过宽异常来掩盖真实故障；确需兜底时明确边界和后续处理。
- 重新抛出异常时保留原始 cause，并补充足够定位业务上下文，但不要泄露敏感信息。
- `finally`、try-with-resources 等资源释放方式优先保证资源在异常路径也能正确关闭。
- 不在 `finally` 中用 `return` 覆盖正常返回或异常。

## 日志

- 使用项目统一日志框架和封装，不混用不同日志体系。
- 日志级别应匹配可操作性：正常业务路径避免滥用 error/warn，真实故障也不要降级为 debug。
- 参数化日志优先于无条件字符串拼接，尤其在高频路径。
- 异常日志保留 stack trace；避免只打印 `e.getMessage()` 导致定位信息丢失。
- 避免同一异常在多个无处理价值的层级重复记录，形成日志噪音。
- 不记录密码、token、完整凭证、敏感个人信息等；必要字段按项目安全规范脱敏。

## 单元测试

- 测试验证外部可观察行为，不绑定无业务意义的实现细节。
- 测试数据应清楚表达场景；避免测试之间依赖执行顺序或共享脏状态。
- 对边界、异常路径和关键业务规则补充有价值的测试，而不是追求形式上的覆盖率。
- Mock 只用于隔离真实外部边界或不稳定依赖，不为了“单元化”复制内部实现结构。
- 修复 bug 时优先保留能稳定复现问题的回归测试。

## 安全

- 外部输入在可信边界进行校验；输出到 SQL、HTML、Shell、日志等不同上下文时使用对应安全机制，不依赖字符串拼接。
- 权限检查在服务端可信边界执行，不把客户端参数当作授权依据。
- 数据库查询使用参数绑定或 ORM 安全接口，避免拼接用户输入形成 SQL。
- 文件、URL、反序列化、表达式执行等高风险入口按实际威胁模型限制输入范围。
- 密钥、token、密码等不得硬编码进源码或日志；使用项目已有秘密管理方式。
- 加密、签名、随机数等安全能力使用成熟标准库和项目既有方案，不自行设计算法。

## 工程约束

- 项目已有静态检查、质量门禁和 CI 规则时，以自动化结果为准。
- 规范问题与业务问题冲突时，优先保证正确性和兼容性；规范改造不应顺带扩大成无关重构。
