# 中文术语审校

把英文概念转换成中国技术团队能够自然理解的表达。翻译概念在当前语境中的作用，不机械对应英文词形。

## 职责边界

只处理术语选择、概念命名和跨文件一致性，不承担整篇文章的语气、句法或结构润色。

- 普通中文表达存在 AI 味、模板句式或翻译腔时，交给中文改写类 Skill。
- 业务概念的含义、边界或代码命名尚未确定时，先进行领域建模；本 Skill 只处理已经明确的概念如何用中文表达。
- 产品名、协议名、代码标识符、命令、路径、API 字段和引用原文默认保持不变。
- 不为“全中文”强译没有稳定译名的缩写、专有名词或社区通用英文术语。

## 判断顺序

按以下顺序决定术语：

1. 读取用户要求、目标仓库的写作规范、术语表和已有同义表达。
2. 确认原词在当前上下文中的实际含义、作用和受众；不要只查英汉词典。
3. 优先采用目标读者已经熟悉且含义准确的行业译名。
4. 没有自然译名时，改写为能够直接说明作用的中文短语。
5. 中文会丢失关键区分或不利于检索时，首次写作“中文（English）”，后续使用中文或约定缩写。
6. 英文已经是代码、协议、产品或稳定专名时保留英文，并通过上下文解释，不造生硬中文名。

含义不确定且会改变译法时，先查原始定义、源码或官方文档；仍无法确定时列出少量候选并说明差异，不擅自定稿。

## 审校原则

- **按语义翻译**：先回答“它在这里做什么”，再决定叫什么。
- **自然优先**：避免为了贴近英文结构而堆叠定语、名词和“……性”“……化”“……式”。
- **必要时展开**：一个自然的说明性短语，通常好过一个貌似专业但难以理解的压缩词。
- **保留专业区分**：自然不等于模糊；不同概念不能因为中文相近而合并。
- **同义一致**：同一概念在同一套文档中使用同一表达；同一个英文词承载不同含义时，不机械统一译法。
- **避免自造术语**：除非项目明确需要命名新概念，否则优先使用现成说法或直接描述作用。
- **尊重既有约定**：仓库已有且没有理解障碍的稳定术语，不为了“更中文”反复改名。

## 典型改法

这些示例用于说明判断方式，不是脱离上下文的固定词典。

| 生硬表达 | 推荐表达 | 判断依据 |
| --- | --- | --- |
| 条件式 high-level-design | 按需概要设计 | 表达“满足条件时才进入”的流程含义，不照搬 conditional 的词形 |
| 跨局部技术契约 | 多处实现共同遵守的设计约定 | 直接说明约束范围和作用，避免堆叠抽象名词 |
| Breadth / Depth | 广度 / 深度 | 中文已有准确、对称且易懂的对应词 |
| capability owner | 能力维护者 / 负责该能力的组件 | 根据语境区分人员职责与组件职责，不固定翻成“能力所有者” |
| execution frontier | 当前可执行任务 | 在调度语境中说明实际作用，不强译 frontier |

## 执行流程

1. 确定审校范围和权威来源，识别必须保持原样的代码、字段、专名与引用。
2. 搜索候选术语及其变体，至少检查标题、正文、表格、链接文字、注释、提示词和 UI 文案。
3. 为每个候选恢复原始概念，判断问题属于误译、硬翻译、含义过宽、含义过窄还是前后不一致。
4. 按判断顺序选择推荐表达；必要时先给用户少量候选，不提供无差别的同义词列表。
5. 修改所有承载同一概念的文本。不要盲目全局替换，应逐处确认语义。
6. 回查旧表达和中英混用残留，确认没有改动代码标识符或破坏原意。
7. 运行目标仓库已有的轻量检查，并报告无法验证的部分。

## 多载体一致性

术语可能同时存在于 Markdown、YAML、HTML、SVG、流程图源文件、图片替代文本和截图说明中。修改时：

- 使用搜索确认同一术语出现在哪些载体。
- 有可生成的图示源文件时，修改源文件并按仓库流程重新生成产物。
- 没有生成流程时，同步修改可编辑的 SVG、HTML 和周边说明。
- 二进制图片中的文字无法安全修改时，明确列为未处理项，不假装已经同步。
- 修改后再次搜索旧术语，并检查链接、转义、布局和渲染是否受影响。

## 输出

用户要求直接修改时，完成修改后只说明：

- 采用了哪些关键术语及理由
- 修改了哪些文件或载体
- 使用什么方式验证，以及是否仍有未处理项

用户只要求审查时，按“原表达 / 问题 / 推荐表达 / 理由”列出有实质影响的条目，不罗列无关的个人风格偏好。

## 最终检查

- 每个译法都来自当前语义，而不是英文词形
- 中文读者无需反向猜测英文才能理解
- 关键专业区分、事实强弱和责任主体没有变化
- 同一概念的 Markdown、HTML、SVG 和提示词表达一致
- 代码、命令、字段、路径、专名和引用没有被误改
- 没有为了统一而把不同语义强行替换成同一个词
